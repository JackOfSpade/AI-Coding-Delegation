## Offload

Use Offload only when the user invokes `/offload_sonnet` or `/offload_opus` as a slash command (for example, `/offload_sonnet <task>`). A mention, quotation, negation, or discussion of `/offload_sonnet`, offload, delegation, DeepSeek, a provider, or a model does not select Offload, nor do bounded, multi-file, implementation, testing, debugging, Workflow, ultracode, or native-subagent requests. Follow the command’s `offload_sonnet` or `offload_opus` skill before using its MCP tools for either supported command invocation. Before a report or `inputFiles` call, use the skill's health preflight: missing/mismatched server schema/capabilities or `sandboxReason` means the live MCP may be stale, so tell the user to restart Claude Code/MCP and do not issue an incompatible report call. Never kill or claim to hot-reload a client process. Route `/offload_sonnet` through profile `sonnet` (latest Sonnet with adaptive thinking), and `/offload_opus` through profile `opus` (latest Opus with adaptive thinking). Omit `effort`. Both fall back to the latest provider-maintained DeepSeek Flash with thinking enabled and high reasoning effort only after explicit promotional-credit exhaustion. Models and trusted price tables are snapshotted; an unknown-priced release fails before spending. The old `/offload` command is removed and never authorizes jobs. Workers cannot use live MCP connectors or other client tools; on policy-only hosts they also have no worker shell, though they can edit permitted private-worktree files with file tools. Work needing those tools must stay with primary Claude. For either command invocation, the command or an accompanying explicit user instruction not to use native subagents overrides Workflow, ultracode, or any session-level native-subagent mode. A standalone instruction not to use native subagents does not select Offload; work directly unless the user separately invokes `/offload_sonnet` or `/offload_opus` as a slash command. Otherwise leave routing to Claude Code, including Sonnet ultracode/native-agent workflows. Keep architecture, security decisions, integration, and final review with the primary agent; respect a user request to work solo. A provider or model name never routes work to Offload or permits inferring a profile. For either command invocation, end every final answer with `Offload: N jobs` or `Offload: 0 — reason`.

Either supported command invocation is a routing and cost constraint: the primary orchestrator may be deliberately expensive. Run the tool/health preflight before task exploration or implementation. For either supported command invocation, if the command skill cannot be loaded, tools or health are unavailable or fail, the server or skill is stale or incompatible, or an Offload failure blocks progress, stop the requested task and report the blocker and recovery step. Do not continue implementation locally, use native subagents, or bypass a failed MCP preflight through the CLI. Resume through Offload after recovery and a fresh passing health check, or without Offload only when the user explicitly changes routing. Supported Offload recovery and primary review, verification and integration of usable worker results remain allowed while the service is healthy. Task size or poor worker suitability does not authorize local completion: use a supported Offload job or stop and explain the limitation.

State-changing calls require normal host approval unless the user deliberately ran `node install.mjs --approval-mode=approve`; that narrow mode approves only Offload tools and can spend budget or integrate/revert a scoped patch without another prompt.

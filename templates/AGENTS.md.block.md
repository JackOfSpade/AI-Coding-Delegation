## Offload

Use Offload only when the user invokes `/offload` as a slash command (for example, `/offload <task>`). A mention, quotation, negation, or discussion of `/offload`, offload, delegation, DeepSeek, a provider, or a model does not select Offload, nor do bounded, multi-file, implementation, testing, debugging, Workflow, ultracode, or native-subagent requests. Follow the `offload` skill before using its MCP or CLI tools for a `/offload` command invocation. Before a report or `inputFiles` call, use the skill's health preflight: missing/mismatched server schema/capabilities or `sandboxReason` means the live MCP may be stale, so tell the user to restart the MCP client and do not issue an incompatible report call. Never kill or claim to hot-reload a client process. By default, route `/offload` worker packages through `offload_start` with the configured profile `pro` (the provider-maintained current DeepSeek Pro route, high effort) and omit `effort`; an explicitly selected supported profile name overrides that default. Never invent a generic “latest Pro” model name: a future major model ID or pricing change requires a trusted package/config update. Workers cannot use live MCP connectors or other client tools; on policy-only hosts they also have no worker shell, though they can edit permitted private-worktree files with file tools. Work needing those tools must stay with the primary agent. For a `/offload` command invocation, the command or an accompanying explicit user instruction not to use native subagents overrides Workflow, ultracode, or any session-level native-subagent mode. A standalone instruction not to use native subagents does not select Offload; work directly unless the user separately invokes `/offload` as a slash command. Otherwise leave routing to the primary client, including native-agent workflows. Keep architecture, security decisions, integration, and final review with the primary agent; respect a user request to work solo. A provider or model name never routes work to Offload or permits inferring a profile. For a `/offload` command invocation, end every final answer with `Offload: N jobs` or `Offload: 0 — reason`.

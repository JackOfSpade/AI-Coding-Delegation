## Offload

Use Offload only when the user invokes `/offload_economy` or `/offload_premium` as a slash command (for example, `/offload_economy <task>`). A mention, quotation, negation, or discussion of `/offload_economy`, offload, delegation, DeepSeek, OpenAI, Terra, Sol, a provider, or a model does not select Offload, nor do bounded, multi-file, implementation, testing, debugging, Workflow, ultracode, or native-subagent requests. Follow the command’s `offload_economy` or `offload_premium` skill before using its MCP or CLI tools for either supported command invocation. Before a report or `inputFiles` call, use the skill's health preflight: missing/mismatched server schema/capabilities or `sandboxReason` means the live MCP may be stale, so tell the user to restart the MCP client and do not issue an incompatible report call. Never kill or claim to hot-reload a client process. Route `/offload_economy` through profile `sonnet` and `/offload_premium` through profile `opus`. Omit `effort`. Both start on OpenAI (`/offload_economy` → latest GPT Terra, `/offload_premium` → latest GPT Sol, high reasoning effort), fall back to Anthropic (`/offload_economy` → latest Sonnet with adaptive thinking, `/offload_premium` → latest Opus with adaptive thinking), and then to the latest provider-maintained DeepSeek Flash with thinking enabled and high reasoning effort, each hop only after that provider's explicit credit exhaustion. Anthropic: an explicit HTTP 400 invalid_request_error credit-balance refusal qualifies; OpenAI: an explicit `credit_balance_exhausted`/`insufficient_quota` refusal qualifies; HTTP 400 alone, rate limits, authentication, network and partial-stream failures never do. Fallback retains edits and conversation, records a transition before spend on the next route and stays on that snapshotted stage across later rounds. Never rewrite old HTTP 400 job records to force fallback; review retained diffs and use the supported recovery actions. Models and trusted price tables are snapshotted; an unknown-priced release fails before spending. The old `/offload` command is removed and never authorizes jobs. Workers cannot use live MCP connectors or other client tools; on policy-only hosts they also have no worker shell, though they can edit permitted private-worktree files with file tools. Work needing those tools must stay with the primary agent. For either command invocation, the command or an accompanying explicit user instruction not to use native subagents overrides Workflow, ultracode, or any session-level native-subagent mode. A standalone instruction not to use native subagents does not select Offload; work directly unless the user separately invokes `/offload_economy` or `/offload_premium` as a slash command. Otherwise leave routing to the primary client, including native-agent workflows. Keep architecture, security decisions, integration, and final review with the primary agent; respect a user request to work solo. A provider or model name never routes work to Offload or permits inferring a profile. For either command invocation, end every final answer with `Offload: N jobs` or `Offload: 0 — reason`.

Either supported command invocation is a routing and cost constraint: the primary orchestrator may be deliberately expensive. Run the tool/health preflight before task exploration or implementation. For either supported command invocation, if the command skill cannot be loaded, tools or health are unavailable or fail, the server or skill is stale or incompatible, or an Offload failure blocks progress, stop the requested task and report the blocker and recovery step. Do not continue implementation locally, use native subagents, or bypass a failed MCP preflight through the CLI. Resume through Offload after recovery and a fresh passing health check, or without Offload only when the user explicitly changes routing. Supported Offload recovery and primary review, verification and integration of usable worker results remain allowed while the service is healthy. Task size or poor worker suitability does not authorize local completion: use a supported Offload job or stop and explain the limitation.

State-changing calls require normal host approval unless the user deliberately ran `node install.mjs --approval-mode=approve`; that narrow mode approves only Offload tools and can spend budget or integrate/revert a scoped patch without another prompt.

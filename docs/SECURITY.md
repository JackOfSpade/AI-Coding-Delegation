# Security notes

`offload` is designed for a fallible or prompt-injected coding worker, not a determined attacker with local code execution. Treat repository content, task text, model output, and command output as potentially hostile.

## Trust boundaries

The worker model does not open the repository itself. The local process exposes bounded `read_file`, `list_dir`, `glob`, `grep`, `edit_file`, `write_file`, `run_command`, and `finish` tools. Returned file text and command output are sent to the provider; the default provider is DeepSeek, with the China-processing and training-use disclosure in the [README](../README.md) and [DeepSeek policy](https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html).

Do not run against repositories containing credentials, regulated information, or instructions you would not send to the configured provider. `denyRead` reduces exposure; it cannot recognize every secret or prevent a command from printing sensitive material on a policy-only host.

## Paths and writes

- A job must declare non-empty relative `ownedPaths`; `..` and absolute paths are rejected.
- File reads and writes resolve real paths and reject lexical traversal, symlink escapes, and paths outside the repository.
- Before creating a missing path, the runtime walks and canonicalizes each existing parent and refuses an intermediate symlink escape. Node does not provide descriptor-relative operations here, so this reduces rather than eliminates same-user time-of-check/time-of-use replacement races.
- Writes require both the logical and resolved path to match `ownedPaths` or caller-only `extraWritable`. `extraWritable` must be disjoint from `ownedPaths`; it is temporary workspace scope whose output is discarded and never integrated or reverted. Repository `.offload.json` cannot grant it.
- The default read denylist covers `.env*`, PEM files, `id_rsa*`, `.aws`, `.ssh`, `.pgpass`, credentials files, common keystores (`.p12`, `.pfx`, `.jks`), Terraform state, and Git paths. Add repository-specific globs through `.offload.json` `denyRead`. The macOS command profile separately denies selected sensitive host-configuration trees even when toolchain roots are readable.
- An edit requires a prior read and a matching content identity/hash. `write_file` has the same complete-prior-read requirement for an existing file, checks it again immediately before rename, and detects a racing creator for a new file. Both write operations reject Git-ignored untracked destinations so a write cannot evade the patch/revert record.
- Built-in jobs use a private linked worktree. Before/after temporary-index snapshots produce review patches without changing the primary checkout. Only successful owned changes are integrated after branch, HEAD, worktree, index, and literal-path conflict checks. A successful verifier is separately checked for post-worker mutation of owned output; scope violations and non-ephemeral ignored output fail without application.

Path controls constrain the supplied file tools. They do not by themselves confine arbitrary commands; that depends on the host sandbox.

## Secrets and records

Keys are references, not config values: `env:NAME`, `keychain:service`, or, on POSIX, an absolute current-user-owned owner-only (`0600`) regular file. Secret files cannot be symlinks. The runtime reads a file secret from one checked descriptor and compares identity, ownership/mode, size, and high-resolution timestamps before and after reading, which rejects deterministic same-size replacement attempts. This narrows but cannot remove the remaining same-user race after the final descriptor check. `keychain:` uses macOS Keychain, Linux Secret Service, or Windows Credential Locker for the signed-in local user. It is deliberately local, not a DeepSeek account-login/session bridge; do not rely on Credential Locker for cross-PC provisioning because behavior depends on Windows account type and policy. The command runner removes environment variables whose names look credential-bearing and supplies a minimal environment; it also changes `HOME` (and `USERPROFILE` on Windows) to a temporary location.

The `file:` permission check is POSIX-mode based. Windows ACLs do not map reliably to `0600`, so use `keychain:` or `env:` on Windows rather than `file:` until native ACL validation is implemented.

Configuration, installer artifacts, MCP skill resources, and managed job storage are read through checked descriptors, with bounded regular-file checks and strict UTF-8 where text is required. Repository config and installer/skill artifacts reject unsafe final symlinks; an explicitly selected global config may be a pre-existing symlink but is still descriptor/identity checked. Job metadata, events, messages, reports, and patches are placed below `.git/offload/`. Private worktrees are created below permission-restricted temporary roots. A terminal result is not published until its lifecycle owner has attempted lease release and private-worktree cleanup and recorded the result. A safe cleanup failure remains retryable and appears as `workspaceCleanupError`; if a persisted record cannot be safely validated to supply its workspace path, recovery records `workspaceCleanupRequired` and an explicit manual-cleanup error instead of touching that path. Durable `refs/offload/jobs/...` snapshot refs remain for retained records, and there is no purge command. On POSIX, the runtime creates persistent artifacts with restrictive owner-only modes. On Windows, Node mode bits do not validate or enforce private NTFS ACLs, so artifact privacy relies on the existing repository and user-profile ACLs plus the trusted-local-user model. Structured sensitive fields, Bearer tokens, common credential assignments/headers, and explicitly configured literal secrets are redacted before persistence. Redaction is heuristic: never intentionally place a secret in task text, source reads, or command output. A patch containing an explicitly configured literal secret is refused for persistence. Patch bytes used for apply/revert are retained and authenticated exactly; the human review display may be visibly lossy for invalid UTF-8 or terminal/bidi controls.

Transcript and artifact publication use sealed pending digests and same-directory atomic renames. Restart recovery can therefore validate either side of an interrupted publication and reconciles interrupted integration/revert before making a terminal lifecycle claim; it also finalizes dead work, releases its lease, and retries safe private-worktree cleanup.

For built-in provider jobs, the full durable record is sealed with a versioned HMAC-SHA-256 under a per-user random integrity root. Each job MAC key is domain-separated and derived from that root, the canonical repository path, canonical git directory, and job ID. At trusted creation, the record also seals its accepted execution `keyRef` and an exact-shape, root-keyed, domain-separated fingerprint of the freshly resolved credential (not a raw credential hash). On normal inspection or any execution path, the MAC is authenticated before the record's `keyRef` is resolved; only then is a newly resolved credential compared with the sealed fingerprint. The seal covers endpoint and `keyRef`, model/pricing/budget, policy/scope, lifecycle/accounting, revert authority, and transcript/patch/report digests before consumption. A changed, unsigned, legacy, root-lost, malformed-root, or credential-rotated record fails closed before provider construction, resume, repair, verification, revert, and ordinary inspection. The narrow operational exception is MAC-verified cancellation, recovery/finalization, and lease cleanup: these never resolve a `keyRef` or construct a provider, so stale jobs can be safely stopped and finalized after credential rotation.

On POSIX the root is one regular, owner-private, non-symlinked file in the hardened external integrity-state directory; creation is create-only and re-reads the checked descriptor. Its location is independent of any caller-supplied config path and never falls back to a repository or git directory. On Windows it is exactly one fixed, internal Resource/account pair in the signed-in user's Credential Locker. This pair is separate from, and cannot be addressed by, the Resource/account mapping used for `keychain:service`; APPDATA, XDG, and custom filesystem state paths are not used for this root. Credential Locker behavior can vary by Windows account and policy, so cross-PC provisioning must not be relied on. There is no per-job or per-repository Credential Locker map.

This is not a general hostile-local-code boundary. Cancel markers and event logs are intentionally separate operational files, and a same-user process that can alter `.git/offload/`, replace the installed program, or use the active provider credential can still disrupt work. The MAC does not authenticate such a compromised account or preserve availability. Before a persisted job is resumed, verified, recovered, or reverted, the runtime also binds its repository to the manager's canonical root, derives write scope from validated declarations rather than stored convenience fields, and accepts only bounded Git object IDs. Do not share a repository or its `.git` directory with untrusted local users or processes.

## Sandboxes and networking

On macOS, when `sandbox-exec` exists, `run_command` uses an allowlist profile: repository and system/toolchain paths are readable, declared roots are writable, and network is denied unless the job explicitly has `allowNetwork: true`. The profile expressly denies the private worktree `.git` pointer, that worktree's Git administration directory, and the primary common Git directory for reads and writes, after its broad repository read rule. It also denies sensitive host configuration locations such as `/usr/local/etc`, `/opt/homebrew/etc`, `/Library/Keychains`, and selected macOS management/security paths. The worker process—not a child command—holds the provider key.

On Linux, Windows, and macOS without `sandbox-exec`, the result is `policy-only`: file-tool rules still apply but shell commands have no OS-level filesystem or network isolation. Worker `run_command` is disabled there. The server-side verifier defaults to requiring an actual macOS sandbox result. The only policy-only exception is a caller-supplied command with explicit `--unsafe-policy-only-verifier` / `unsafePolicyOnlyVerifier` consent; repository-configured verification cannot use it. Use that exception only for trusted local code: its result can never trigger automatic or later `repair`. On Windows, timeout/cancellation uses `taskkill /T /F` as a best-effort process-tree stop. Even on macOS, `sandbox-exec` is deprecated and must be tested with the actual toolchain.

`allowNetwork` affects worker and verifier commands, not the local process's HTTPS call to the model provider. Extra writable paths increase command/filesystem scope; keep them narrow and treat all resulting files as ephemeral.

For a finite `maxUsd` job, each provider turn is single-attempt. Retrying a lost or malformed streamed response may create a second billable request without a reliable first usage record, so capped jobs fail rather than automatically retry. Uncapped/direct provider use retains its configured transient-retry behavior.

## Prompt injection and operations

Repository instructions can attempt to override the job. The system prompt tells the worker to honor scope and never access secrets, but model compliance is not a security control. Use narrowly scoped jobs, explicit acceptance criteria, a restrictive `ownedPaths` list, and a minimal `testCommand`. Review `offload job <id> --include diff` and the final report before accepting changes.

On timeout or cancellation, POSIX hosts terminate the command process group (then escalate to `SIGKILL` after a short grace period); Windows requests `taskkill /T /F`. Inspect for unusual child processes if a command uses a platform-specific launcher or has escaped that best-effort stop. `cancel` first writes an idempotent durable marker, including when a separate CLI/MCP process does not own the detached worker. Such a request can acknowledge before the worker owner observes it, so wait for a terminal `CANCELLED` result before assuming the process tree or workspace is settled. `cancel` preserves a private review patch, but never applies it. `revert` is available only for an already integrated owned patch; use its dry run, review conflicts, then pass `--apply` only when safe.

## Reporting a problem

Do not include API keys, full sensitive files, or unredacted job artifacts in a report. Provide the offload version/commit, platform, `offload doctor` output, the non-sensitive job id/status, and minimal sanitized reproduction steps. For a suspected secret leak, rotate the secret first, restrict access to `.git/offload/`, and report only redacted evidence.
